# Безопасность

> [English](SECURITY.md) | **Русский** | [中文](SECURITY.zh.md)

Рецепты по контракту не содержат учётных данных (CI отклоняет строки, похожие на секреты).
Если вы всё же нашли такую — или рецепт по умолчанию запускает что-то небезопасное
(широкие bind, отключённая авторизация) — заведите issue. Мы исправим и перепроверим.

## Политика авторизации
- API по умолчанию требует ключ (`API_KEY` экспортируется в сервер как `VLLM_API_KEY`).
- `ALLOW_NO_AUTH=1` принимается **только вместе с `BIND=127.0.0.1`** (loopback-отладка,
  закрытый контур, ответственность за который вы принимаете). Любой не-loopback bind требует
  API-ключ независимо от `ALLOW_NO_AUTH` — публичный неаутентифицированный API всегда
  отклоняется.
- Адрес сервера задаётся исключительно аргументом `--host "$BIND"` (host-сеть делает
  docker `-p` пустышкой; лаунчеры не притворяются иначе).
- Секреты никогда не попадают в вывод лаунчера; они существуют только внутри окружения
  контейнера.

## Модель угроз
- **Окружение контейнера можно прочитать.** `VLLM_API_KEY` передаётся через `docker run -e`;
  любой, кто может запустить `docker inspect` на хосте, его увидит. Доступ к docker эквивалентен
  root — ограничивайте, кто им обладает. Для многопользовательских/сетевых развёртываний ставьте
  прокси аутентификации и держите ключ вне окружения контейнера.
- **`--trust-remote-code`** исполняет собственный Python модели. Фиксация `MODEL_REVISION`
  предотвращает незаметные изменения при повторных загрузках, но не делает код безопасным.
  Изучите remote-code модели до первого запуска; запускайте контейнер без лишних монтирований
  и секретов хоста.
- **Манифест патчей** (`patches/MANIFEST.sha256`) ловит наивные подмены, но лежит рядом с
  патчами — для повышенной гарантии закрепляйте и сверяйте ревизию git, которую вы ревьюили.
