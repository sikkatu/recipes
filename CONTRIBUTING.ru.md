# Как внести рецепт

> [English](CONTRIBUTING.md) | **Русский** | [中文](CONTRIBUTING.zh.md)

Рецепт — это обещание: *на этом именно железе, с этим именно ПО, эта команда даёт эти цифры,
измеренные таким образом.* Всё в этом файле существует, чтобы это обещание мог проверить
посторонний человек с такой же машиной.

## Контракт
Каждый рецепт живёт в `recipes/<hardware-slug>/<recipe-slug>/` и содержит:
| файл | назначение |
|---|---|
| `recipe.yaml` | **Обязателен для статусов `experimental`/`verified`/`deprecated`; `draft` может его не иметь** (тогда индекс показывает черновик по H1 README, а `check_recipe.py` запрещает любые не-draft заявления в черновом README). Машиночитаемый пин: ревизия модели, digest образа, железо **по наблюдению**, команда запуска, метрики с провенансом, ворота, ограничения, откат. Проверяется `schemas/recipe.schema.json` + `scripts/check_recipe.py` в CI. |
| `README.md` | человеческая страница. Только текущее состояние — без дневника. Обязательные разделы: `What this runs`, `Hardware`, `Software`, `Launch`, `Verify`, `Results`, `Known limits`, `Rollback`. |
| `scripts/` | скрипт запуска из README, плюс ожидание health, прогрев, бенчмарк, откат. То, что вы запускали, а не приукрашенная версия. |
| `results/<run-id>/` | пакет провенанса для каждой опубликованной цифры: `system.json` (из `scripts/collect_system_snapshot.sh`), digest образа, ревизия модели, точная команда запуска, сырой вывод бенчмарка/качества, обрезанные логи. |
| `known-limits.md` (опц.) | развёрнутая форма `limits:`, когда нужно объяснить компромиссы. |
| `research/` (опц.) | журналы, разборы причин, неудачные эксперты. Приветствуется — то, что не заработало, это половина ценности. |
| `patches/` (опц.) | код, который рецепт монтирует в контейнер; каждый файл перечислен в `recipe.yaml` с его sha256. |

## Правила, которые проверяет чекер
- **Никакого `:latest`.** Образы — `name:tag` плюс дайджест `sha256:`.
- **Ревизии моделей — 40-символьные commit SHA**, никогда имена веток.
- **Железо — то, что сообщает машина**, а не спецификация. `hardware.observed` должен указывать
  на `results/<run-id>/system.json`, из которого он получен.
- **У каждой метрики есть провенанс**: `run_id`, `method` и сырой файл `raw`, из которого
  число считалось — и этот файл должен существовать.
- **`status: verified` требует**, чтобы каждое ворото (`schema`, `digest`, `health`, `quality`,
  `performance`) имело `last_pass_utc` и `run_id`, и хотя бы одну опубликованную метрику.
- **Никаких учётных данных** нигде в дереве. API-ключи читаются из файлов вне репозитория
  во время запуска.
- **Патчи совпадают со своими sha256.**

## Правила, которые проверяют люди (ревью PR)
- Число без формы нагрузки (конкурентность, длины prompt/output, класс prompt) — не число.
- Если число измерено до фикса, оно несёт `label:` и README говорит об этом рядом.
- Качественные ворота — **на рецепт и заявлены**. Один рецепт может принимать FP8 KV cache;
  другой — запрещать. Ни один из них не является «эталоном» — эталон тот, что рецепт
  объявляет и измеряет.
- `Known limits` необязателен лишь формально: если вы не нашли ограничений — вы не смотрели.
- Откат должен быть скриптом, а не предложением.

## Значения статусов
| статус | означает |
|---|---|
| `draft` | пишется; может не запускаться |
| `experimental` | запускается и есть цифры, но какое-то ворото не измерено или открыт известный дефект |
| `verified` | все пять ворот прошли на записанном запуске; посторонний с такой машиной воспроизведёт главную цифру в пределах ~5% |
| `deprecated` | заменён или ПО ушло вперёд; сохранён для истории |

## Рабочий процесс
```bash
uv venv .venv && uv pip install -p .venv/bin/python jsonschema pyyaml pytest numpy pillow
.venv/bin/python -m pytest tests -q
.venv/bin/python scripts/check_recipe.py --all
.venv/bin/python scripts/render_index.py
```
Откройте PR; CI выполняет те же четыре команды. Ревью фокусируется на провенансе, а не на прозе.

## Атрибуция
Рецепты стоят на чужих ядрах, движках и чекпоинтах. Укажите авторов использованного по имени
и ссылкой в README рецепта. Сначала измерьте, потом спорьте с ними.
